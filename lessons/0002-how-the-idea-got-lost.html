Hypermedia: the architecture we forgot

The web shipped with facts and controls in one document. Then the industry spent a decade separating them. This section shows how the idea began, what replaced it, and what the separation cost.

Section 02

How the idea got lost

The loop you saw in Section 01 has a history. Ted Nelson described hypertext in 1965. Roy Fielding named the style REST in 2000. By 2011, teams were moving to data contracts. The shift took decades, and it happened one request at a time. This section traces the arc, weighs the reasons, and names the cost.

Before you read on, can you name the loop in four words?

Request. Document. Choice. Next document.

Trace the idea

In 1965, Ted Nelson coined two words: hypertext and hypermedia. Hypertext means text that branches. Hypermedia extends the same idea to audio and video. Both words describe the same mechanism: documents that point at other documents. It took twenty-four years for that idea to reach the form that stuck: linked documents and their controls together, on a network nobody owned.

In 1989, Tim Berners-Lee did it. He proposed the idea in a document at CERN, then built it: linked documents, read by a client no one owned. Those documents carried both facts and controls. That mix is the part the industry later lost.

In 2000, Roy Fielding named the style in his doctoral dissertation: REST. You met his words in Section 01. One part is often missed: the controls must travel with the facts. Without that, the architecture is not REST.

Each step in the timeline shows who holds the next move.

Do it now

Open any shop you already use and put an item in the basket. Then open DevTools with Ctrl+Shift+I (or Cmd+Option+I), choose the Network tab, and find the JSON reply. The page rebuilt its own buttons from code. The next moves live in the client, not in the document.

Trace the drift

Data contracts came from a real need. Enterprise software wants reliable conversations, so it freezes them into contracts. A schema describes every message; a stack generates the code. Servers answer with data, not with the next move.

In 2005, the shift happened inside a page. AJAX, Asynchronous JavaScript and XML, let a site update in place without a reload, and the word “API” replaced “server” in ordinary talk. JSON borrowed the shape of JavaScript’s object literals, so a browser reads a payload without any document controls. No one voted to stop sending controls. The move from controls to data happened request by request. You do not need to know how AJAX works yet.

By the late 2000s, native apps were everywhere. The shift held for four separate reasons, and each one was real:

  1. Native apps were everywhere, and each one had its own screen.
  2. Screens animate in place, and a full reload cannot follow.
  3. Teams found a fixed contract easier to test and to version.
  4. Tooling could generate client code from the fixed shape.

A shift that holds for four separate reasons does not reverse easily. Weigh which were necessity, which were fashion, and which was the cost.

Weigh the reasons

Sort the decade yourself before the rows explain it. The three rows are Necessity, Fashion, and the Cost. Nothing here is an insult; all three forces are honest mechanics. Necessity earns its place, fashion follows habit, and cost lands on someone who pays it. Do not try to memorize the definitions. Arrange the reasons, and the pattern names itself.

The JSON decade, in review

Review the three rows you just sorted.

  1. Necessity earns its place: native apps, animation, and testable contracts.
  2. Fashion follows habit: data without the next move, and a spec kept outside the document.
  3. The cost lands on the client, which must be rebuilt and shipped whenever rules change.

See what the name lost

The loss shows in how the word is used. HATEOAS, Section 01’s name for the rule that the document carries the next move, shrank in practice to a JSON field of links. A link you must already know is a note, not a control. In common use, REST came to mean facts alone.

Fielding objected in public. In 2008 he restated the rule: REST APIs must be hypertext-driven. Section 01 quoted that piece. The name outlived the author’s meaning.

In 2011, Swagger fixed the shape of the conversation, field by field. A decade of WSDL had left the industry with complex contracts; a plain testable shape came as a relief. The spec, now under the name OpenAPI, still defines the conversation today. Teams receive exact expectations and give up the open-ended loop. The document that carried controls gave way to a schema that describes data.

Check what survived

The older loop never completely disappeared. Documentation sites, forums, and plain web apps kept it running. New tooling, including htmx and Hotwire, returned to the same idea: send the document, and let it carry the moves.

Check yourself

Three questions. Answer each one before you open it.

It is 2005. The cart updates without a reload. Where does the next move now live?

In the client’s code. The page rebuilt its own buttons, so the manual moved out of the document and into the JavaScript that receives the payload.

A service returns JSON with a labeled _links map. Is that hypermedia in Fielding’s sense?

Not on its own. A label a client must already know is a note, not a control. Hypermedia travels with the way to act.

Say what the separation cost, in one sentence.

The client now holds the manual. Every rule change becomes a rebuild and a new release.

With all three rows on the table, here is the question: which parts of the JSON decade were necessity, which were fashion, and which was the cost?
