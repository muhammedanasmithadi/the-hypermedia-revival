The status line names what happened

Section 01 ran one flow: request, document, choice, next document. Section 03 put two flows on one table. Every reply carried a verdict, and the page read it and moved on. This section names the first line of every reply: the status line. The line closes with three digits that tell the client what just happened.

Before you read on, what did the terminal say when you asked it for $50 it did not hold?

It refused. It answered “The machine refused: you only have $40.” That refusal was a verdict, and verdicts have classes.

Read the verdict

The status line opens every HTTP, Hypertext Transfer Protocol, reply. The code is data, not prose. A browser reads it without a dictionary and decides what to do next. You do not need the header lines yet. The three digits carry the idea.

Seven requests sit below. Read each one, name the class that fits, and flip the card to read the verdict. You may not know every code yet. That is the point: name the class, then check.

Do it now

Open DevTools with Ctrl+Shift+I (or Cmd+Option+I), reload, and look at the Network tab. Find the request for this page and read its status line: 200. Change the address to a page the course does not ship, such as 0009-does-not-exist.html, and watch the next reply arrive with 404. The class tells you what happened before the body does.

The five classes, in review

Review what the verdicts just showed you.

  1. 1xx is informational. Browsers keep it out of sight.
  2. 2xx means the request worked, and state moved.
  3. 3xx means look elsewhere, or keep your stored copy.
  4. 4xx means the client asked for something the state would not give.
  5. 5xx means the server broke before it answered.

Name the five classes

Three digits, five classes. The first digit names the class. The other two name the detail. 2xx means the request worked. 3xx means the client should look elsewhere, or reuse what it keeps. 4xx means the request fell because of the request itself. 5xx means the server fell before it could answer.

One class answers to one client rule. A generic browser acts on the class without knowing each code by heart. The page you are reading did not parse a dictionary of codes. It branched on the first digit.

You may wonder why a reply needs three digits and not two. The third digit lets the server say more without changing the class. 200 and 201 both tell the client the request worked. One says the reply carries the document; the other says a new resource appeared.

Meet the codes that matter

The kiosk in Section 01 answered with one page for each move. Its bank would answer with codes too. Seven codes carry almost every reply you will read:

200 OK carries a full document. Every balance page in the kiosk earned it. 201 Created says a move made a new resource. Open a new account and the reply names it. 204 No Content says the state changed and the reply carries no body. A payment lands, and the balance page does not need to come again.

303 See Other says the answer lives at another URI. The client follows the location the reply names. 304 Not Modified says your stored copy is still good. The mechanics wait for Section 06; for now, read the verdict. 404 Not Found says the target does not exist in the server state. Ask for account 4042, and no account answers. 500 Internal Server Error says the server broke while it tried to answer.

Treat 404 as data, not as an accident. The client asked for something the server state does not hold, and the server said so plainly.

Act on the class

The browser acts on the class, and the reply still carries its moves. Section 03 showed the reply in building A with its form inside. That reply opened with a status line too: 200, then the document. The first digit decided the move. The document named the next click.

Both replies in that table were 200. The verdict does not say who owns the next move. It says the request worked. Section 02 named the cost of the JSON decade. The status line stays the same on both sides of that table; the body is where the moves live or leave.

Here is the bridge this section builds: the status line names what happened, and the document names what comes next. 404 earns its place because each URI is its own state. Ask for a URI the state does not hold, and the class answers for it.

Check yourself

Three questions. Answer each one before you open it.

You ask for a page the server state does not hold. Which class answers?

4xx, the client error class. The state holds no such page.

A move creates a new resource on the server. Which code marks the creation?

201 Created. The move made a new resource, and the reply names it.

The terminal refused your $50 withdrawal. Which class did that refusal carry?

4xx. The client asked for something the state could not keep.

One line, three digits, five classes. You can now read what happened before you read how. The next sections put those digits to work. Section 05, “Ask without harm. Repeat without doubt,” asks which moves you may send twice. Section 06 shows the stored-copy handshake that earned the 304 in the cards.
