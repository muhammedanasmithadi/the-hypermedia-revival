Glossary

The terms of the course, in one place. Each entry names the section that teaches it.

Hypertext
Text that branches. One document points at another, and the reader chooses the next one. Learned in Section 02
Hypermedia
Hypertext extended to audio and video. The document carries the facts and the controls together. Learned in Section 01
Contract
The shared shape of the data between a client and a server. Under a contract, the client learns the moves from its own code, not from the reply. Learned in Section 02
REST
The style Roy Fielding named in 2000. The document carries the facts, and the controls travel with them. Learned in Section 01
HATEOAS
Hypermedia as the engine of application state. The server names the next moves in the reply, so the client keeps no manual of its own. Learned in Section 01
Status line
The first line of every HTTP reply. It carries the three-digit code and the reason phrase that name what happened. Learned in Section 04
Safe method
A method that must never change server state. GET, HEAD, and OPTIONS are safe. The server can repeat them freely. Learned in Section 05
Idempotent method
A method that may change server state, but repeating it produces the same result as doing it once. GET, HEAD, PUT, DELETE, and OPTIONS are idempotent. Learned in Section 05
